5. **How a JSON-owned tree/HSM definition is registered** (§6.3, Q3):
   The bridge calls `coreClass.Build()` (the `[BTreeDefinition]` thunk) to get the `BehaviorTreeBlob`, wraps it in `Interpreter<BrainBlackboard, BTreeContext>(blob, registry)`, and calls `beh.Register(id, name, new BehaviorDefinition { BTreeInterpreter = interpreter, ... })`.    `FbtTreeCatalog` (generated by the parallel `BTreeDefinitionGenerator`) cannot see JSON-owned definitions emitted in-memory — so the bridge **self-registers** into the staging `BehaviorRegistry`, giving the runtime full awareness of the definition.

6. **Editor-owned trees are unwired at runtime today** (`FDP/Toolkits/Fdp.Toolkits/Behavior/AiHotReloadCoordinator.cs` — confirmed at branch HEAD):

**Bug fixes discovered during verify-first** (not in spec, required for correct implementation):

- **BTree `[BTreeDefinition]` attribute `AssetId` named arg**: `BTreeDefinitionAttribute` (Fbt.Kernel) has no `AssetId` property. The `BTreeEmitCore.EmitBuild` was emitting `[BTreeDefinition("Name", AssetId = "...")]` which fails Roslyn compilation. Fixed: removed `AssetId = "..."` from the emitted `[BTreeDefinition]` call (AssetId is already in the file header comment). `HsmDefinitionAttribute` correctly has `AssetId { get; set; }` — HSM unchanged.

- **HSM forward-reference in transitions** (`HsmEmitCore.EmitCreateBuilder`): The original emitter interleaved `state.On("Evt").GoTo("TargetState")` calls inline with state declarations, causing `InvalidOperationException("Target state 'X' not found")` at runtime because the target state wasn't yet registered in the builder. Fixed: added a **two-pass emission** — Pass 1 emits all state variable declarations + config chains + children; Pass 2 emits all transitions. The `EmitTopLevelState` method is unchanged (used by the full `Emit()` for the committed BATCH-02 gate); only `EmitTopLevelStateDecl` (new) + `EmitCreateBuilder` restructured for the topology-core path.

- **BTree blob has no explicit root node**: `BTreeBuilder.Compile()` does NOT add a `NodeType.Root` wrapper; the blob starts with the first composite node (Sequence). The `BTreeEmitCore.EmitCreateBuilder` was looking for `BTreeRootNodeDto` to find the entry, producing an empty builder when none existed. Fixed: if no `BTreeRootNodeDto` is found, emit the first DTO node directly as the entry, matching the `new BTreeBuilder<>().Sequence(...)` pattern.

**Bridge shape emitted (BTree, per SampleScout):**

```csharp
// HROT_EDITOR_GENERATED - manual edits to this file will be overwritten by the AI editor on next save.
// AssetId: 54ef3847-0000-0000-0000-000000000000

using Fdp.Toolkit.Behavior;
using Fdp.Toolkit.Behavior.Components;
using Fdp.Toolkit.Blueprints;
using Fdp.Toolkit.Blueprints.Attributes;
using Fbt;
using Fbt.Runtime;

namespace Hrot.AI.Behaviors.Trees;

[BlueprintRegistrar]
public static class SampleScoutRegistrar
{
    /// <summary>
    /// Coordinator-injectable registrar (§3 D14, PU-203).
    /// Registers the JSON-owned BTree definition and action/condition thunks.
    /// Called by AiHotReloadCoordinator during hot reload.
    /// </summary>
    public static void Register(BehaviorRegistry beh, BlueprintRegistryStaging staging)
    {
        // Build the blob from the topology-core thunk.
        var blob = SampleScout.Build();
        var actionRegistry = new ActionRegistry<BrainBlackboard, BTreeContext>();
        var interpreter = new Interpreter<BrainBlackboard, BTreeContext>(blob, actionRegistry);

        // Register the JSON-owned definition (FbtTreeCatalog cannot see in-memory defs).
        beh.Register(553838376, "SampleScout", new BehaviorDefinition
        {
            Name         = "SampleScout",
            BrainTier    = BehaviorConstants.BrainTierBTree,
            BTreeInterpreter = interpreter,
        });
    }
}
```

HSM bridge analogously calls `SampleGuard.Compile()` → `beh.Register(id, name, new BehaviorDefinition { HsmDefinition = blob })`.

The bridge is emitted as a **separate class** (`{Name}Registrar`) from the topology-core class (`{Name}`), using a separate hint name `{Name}.Registrar.g.cs`, so PU-205 topology-core equivalence (which compares only `{Name}.g.cs`) stays green.

The **stable ID** is computed via FNV-1a-32 over the 16 asset GUID bytes — deterministic, not `string.GetHashCode()` (which is process-randomised, DEBT-006).

**How the integration test compiles + scans + ticks:**

1. Load `SampleScout` via `BTreeAssetContributor.LoadFrom(BehaviorsAssembly)` → reflection-loaded `BehaviorTreeAsset`
2. `ToDtoWithTypeNames(model, "SampleScout")` — maps to DTO + fills in `BlackboardTypeName`/`ContextTypeName` from the `CreateBuilder()` generic return type (pre-existing limitation: `BTreeAssetContributor.RegisterBlobCore` passes `string.Empty` for type names)
3. `BTreeJsonServices.Serialize(dto)` → JSON
4. Run `BTreeJsonGenerator` via `CSharpGeneratorDriver` → 2 source files: `SampleScout.g.cs` (topology core) + `SampleScout.Registrar.g.cs` (bridge)
5. `CompileMultiAndLoad(srcs, assemblyName)` — two `SyntaxTree` entries compiled via `CSharpCompilation.Create` + `MetadataReferenceResolver.ForRuntimeAssemblies(AppDomain.CurrentDomain.GetAssemblies())` → collectible ALC
6. `coordinator.ScanForRegistrars(asm)` → finds `SampleScoutRegistrar` decorated `[BlueprintRegistrar]`, `Register` method, 2 params `(BehaviorRegistry, BlueprintRegistryStaging)`
7. Invoke `Register` via reflection with staging `BehaviorRegistry` + `BlueprintRegistryStaging`
8. Assert: `stagingRegistry.TryGetId("SampleScout")` == true; definition's `BTreeInterpreter` != null; `BrainTier == BrainTierBTree`
9. **Tick**: `interpreter.Tick(ref bb, ref state, ref ctx)` → `NodeStatus.Running` (Wait nodes not yet elapsed) — no throw
10. HSM analogous: `SampleGuardRegistrar` → `BrainTier == BrainTierHsm`, `HsmDefinition != null`

## Design Decisions

1. **Bridge in separate hint-name file**: Using `{Name}.Registrar.g.cs` as a separate source output instead of appending to `{Name}.g.cs`. This is required by the Roslyn incremental generator API (`spc.AddSource` with distinct hint names) and ensures the PU-205 topology-core equivalence test can isolate the core file by name prefix.

2. **Stable ID from FNV-1a-32 over GUID bytes**: `BTreeBridgeEmitCore.DeterministicIdFromGuid` uses FNV-1a-32 (not `GetHashCode()`, which is process-randomised). Shared between BTree and HSM bridge emitters. The ID is embedded as a literal in the generated code.

3. **Two-pass HSM emission**: The BATCH-03 emitter had a latent bug where transitions were emitted interleaved with state declarations, causing forward-reference runtime errors. The fix adds `EmitTopLevelStateDecl` for Pass 1 (declarations only) and emits transitions in Pass 2. The original `EmitTopLevelState` (full emitter path) is preserved unchanged so the BATCH-02 byte-identical gate continues to pass.

4. **`ToDtoWithTypeNames` helper in integration tests**: The `BTreeAssetContributor.RegisterBlobCore` pre-existing limitation (passes `string.Empty` for blackboard/context type names) means reflection-loaded DTOs have empty type names, producing invalid `BTreeBuilder<,>` (unbound generic). The test helper reflects `CreateBuilder()` return type generic args to fill these in before serializing to JSON.

5. **`InternalsVisibleTo` addition**: Added `Hrot.AiEditor.Generators.Tests` to `FDP/Toolkits/Fdp.Toolkits/Fdp.Toolkits.csproj` so the integration tests can call `coordinator.ScanForRegistrars(asm)` (internal method). Alternative: reimplement the scan inline in the test. Chose `InternalsVisibleTo` to prove the coordinator's actual internal logic is exercised.

## Deviations

1. **`BTreeEmitCore.EmitBuild` — removed `AssetId = "..."` from `[BTreeDefinition]`**
   - **WHAT**: `[BTreeDefinition("Name", AssetId = "GUID")]` → `[BTreeDefinition("Name")]`
   - **WHY**: `BTreeDefinitionAttribute` (Fbt.Kernel) has no `AssetId` property; the named argument was invalid C# that would fail Roslyn compilation of the generated code.
   - **BENEFIT**: topology-core now compiles when fed through the in-memory Roslyn compiler.
   - **RISK**: Low. The `AssetId` is already in the file header comment. BATCH-02 byte-identical gate passes because both sides (adapter + core) use the same fixed emitter. PU-205 equivalence is emitter-vs-emitter so both sides changed together.

2. **`HsmEmitCore.EmitCreateBuilder` — two-pass state/transition emission**
   - **WHAT**: All state declarations are emitted before any transition calls (was interleaved).
   - **WHY**: `HsmBuilder.GoTo("State")` throws at runtime if the target state isn't yet registered; interleaving caused forward-reference failures.
   - **BENEFIT**: generated HSM code is compilable and tickable.
   - **RISK**: Medium. BATCH-02 `SaveHsmEmitTests` still passes (both sides changed together in emitter-vs-emitter comparison). PU-205 equivalence still passes (generator driver uses the same fixed emitter). The changed output order may differ from the committed `SampleGuard.cs` — this is acceptable because the BATCH-02 gate doesn't compare against the committed file (per DEBT PU-D04, that comparison is deferred to PU-401).

3. **`BTreeEmitCore.EmitCreateBuilder` — rootless-blob entry point fallback**
   - **WHAT**: When no `BTreeRootNodeDto` exists in DTO, use `dto.Nodes[0]` as entry.
   - **WHY**: `BTreeBuilder.Compile()` does not add a `NodeType.Root` wrapper; reflection-loaded blobs start with the first composite node.
   - **BENEFIT**: generated BTree code produces a compilable, non-empty `CreateBuilder()`.
   - **RISK**: Low. For hand-authored models that DO have an explicit root, the existing `BTreeRootNodeDto` path is taken. The rootless fallback only fires for reflection-loaded blobs.

## Developer Insights

### Issues encountered and resolved

1. **`BTreeDefinitionAttribute` has no `AssetId` property**: This was a latent BATCH-03 bug — the emitter produced `[BTreeDefinition("Name", AssetId = "...")]` which is invalid C# (CS0246 "AssetId type not found", CS7003 unbound generic). The bug was invisible in BATCH-03 because the generated code was never actually compiled via Roslyn. Discovered and fixed as part of the verify-first in BATCH-04.

2. **HSM forward-reference in `EmitCreateBuilder`**: Another BATCH-03 latent bug — interleaved state + transition emission causes `GoTo("TargetState")` to throw when the target isn't yet registered. Again invisible in BATCH-03 because the generated code was never compiled. Discovered via integration test.

3. **BTree blob has no root node**: `BTreeBuilder.Compile()` does not emit a `NodeType.Root` wrapper — the blob starts at the first composite node. The emitter assumed an explicit root node existed. Fixed by adding a rootless-blob fallback path.

4. **`BTreeAssetContributor.RegisterBlobCore` drops type names**: The contributor passes `string.Empty` for `blackboardTypeName` and `contextTypeName` to the projector. This is a pre-existing limitation. Integration test works around it by reflecting the `CreateBuilder()` return type generic args. Tracked as context for future work (should be fixed in PU-301 / the load-path batch).

5. **`MetadataReferenceResolver` / `InMemoryRoslynCompiler` are net8.0-only**: `Hrot.Blueprints.Compiler` is net8.0 (not netstandard2.0). Adding it as a direct project reference to the test project was the right approach. The `InternalsVisibleTo` in `Fdp.Toolkits.csproj` is the minimal change to exercise the coordinator's actual `ScanForRegistrars`.

### Weak points spotted

- **`BTreeAssetContributor.RegisterBlobCore` type names**: Passes `string.Empty` for blackboard/context type names. This will need to be fixed in PU-301 (JSON load path) or the generated topology core will have `BTreeBuilder<,>` for all reflection-loaded assets.
- **`SaveBTreeEmitTests` / `SaveHsmEmitTests`** only compare string equality between two emitters — neither compiles or runs the generated code. This allowed the three latent bugs above to survive until the bridge integration tests required actual compilation.
- **PU-D04 debt** (from BATCH-03 review): the PU-205 equivalence test still doesn't compare generated output to the committed `SampleScout.cs`/`SampleGuard.cs` directly. The two-pass HSM emission change produces different code order from the committed files. This is acceptable now (both the generator and `EmitTopologyCore` were fixed together), but the direct comparison gate should be added at PU-401.

### Performance observations

- In-memory Roslyn compilation (~800ms per test) is within acceptable range for integration tests. The 11 new tests take ~1s total (running concurrently with discovery/dispatch overhead).

## Known Issues

1. **`BTreeAssetContributor` type name gap**: Integration tests use `ToDtoWithTypeNames` workaround. The root cause (contributor drops type names) is not fixed here — deferred to PU-301.
2. **Two-pass HSM emission now diverges from committed `SampleGuard.cs`**: The two-pass order puts transitions after all states, which is CORRECT for compilation but differs from the committed file's format. PU-D04 direct comparison (deferred to PU-401) will need to account for this.
3. **`EmitTopLevelState` (old single-pass)** is still the code path for `Emit()` (full emitter with layout). For hand-authored models that correctly declare states before transitions, this is fine. For reflection-loaded models used with the full emitter, the same forward-reference risk exists in the layout path — but this is OK because the layout path is only used when writing to committed `.cs` files (editor save), not for the JSON-generator path.
