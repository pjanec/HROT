In the editor subsystem, visually edited Behavior Trees (BTrees) and Hierarchical State Machines (HSMs) are persisted using a strictly code-first approach, which differs significantly from how Blueprints are saved.

BTree and HSM Persistence (C#-Based)

For BTrees and HSMs, the visual editor uses a "code-as-the-source-of-truth" architecture. When you save your visual graph, there are no JSON files or sidecars created. Instead, the editor uses a `FluentCSharpEmitter` (`BTreeFluentEmitter` or `HsmFluentEmitter`) to deterministically completely rewrite the underlying C# file.

This generated `.cs` file contains three methods:

-   **The Builder Method:** The structural definition of the tree or state machine (e.g., `CreateBuilder()`).-   **The Definition Thunk:** Decorated with `[BTreeDefinition]` or `[HsmDefinition]`, which the runtime uses to compile the bytecode.-   **The Layout Method:** Decorated with `[BTreeLayout]` or `[HsmLayout]`, this method stores all editor-only visual metadata, such as canvas positions, zoom levels, node comments, and collapse states.

When the editor opens a BTree or HSM, it does not parse files from disk. Instead, it reflects over the compiled, hot-reloadable assembly to find the definition and layout methods, and projects them back into the visual canvas.

Blueprint Persistence (JSON-Based)

Blueprints operate on a data-driven model and are persisted as pure JSON files with a `.bp.json` extension.

When you save a Blueprint, the `SaveActiveBlueprintCommand` uses `BlueprintJsonServices` to serialize the in-memory Blueprint asset directly to disk. Visual metadata, such as node coordinates (X and Y), canvas pan/zoom, and user comments, are stored directly inside the JSON structure within `EditorMetadata` blocks.

Key Differences Summary

-   **Storage Format:** BTrees and HSMs are persisted as pure, deterministic C# code containing fluent builder API calls. Blueprints are persisted as structured `.bp.json` text files.-   **Loading Mechanism:** The editor reads BTrees and HSMs by loading the compiled assembly and reflecting over the types and `[...Layout]` attributes. Blueprints are loaded by reading and deserializing the JSON files directly from the file system.-   **Code Generation Pipeline:** Because BTrees and HSMs are saved as C# files, they are compiled by MSBuild directly. Blueprints rely on a Roslyn incremental source generator to translate the saved `.bp.json` files into executable C# code during the build process.
