# RR-03 — BTree wire reroute support

**Workstream:** RR (../RR-PLAN.md). **Layer:** Hrot.BTree.Editor model + sink + persistence (DTO/mapper/emitter). **Depends:** none (pattern validated by RR-01/02). **Size: larger** — BTree has no edge objects or waypoint store; add one + persist it.

## Design (locked)

BTree links are derived parent→child edges. `BTreeParentChildLink` (`Model/BTreeGraphModel.cs`) keys its `LinkId` on the **child's VisualId**: `Id = XorGuid(child.VisualId, LinkIdXorKey)` — exactly ONE link per child (the edge up to its parent). Therefore waypoints are a **per-child** property: store them on the child node's editor data (the edge connecting that child to its parent). This reuses the existing per-node metadata persistence.

- **LinkId ↔ child:** `XorGuid` is self-inverse (XOR), so `childVisualId = XorGuid(linkId.Value, LinkIdXorKey)`. Add `internal static Guid ChildVisualIdFromLinkId(LinkId)` on `BTreeParentChildLink` (reuse the existing `XorGuid` + `LinkIdXorKey`; do not duplicate the constant).

## Implementation

1. **Model store (`Model/BehaviorTreeAsset.cs`, `BTreeEditorNode`):** add `public List<Vector2> Waypoints { get; } = new();` (the waypoints of the edge from this node up to its parent). `Vector2` = `System.Numerics.Vector2`.

2. **Expose on the link (`BTreeParentChildLink`):** change `Waypoints => Array.Empty<Vector2>()` to return the child's waypoints. The ctor already receives `child` — store it (or copy the list reference) and return `child.Waypoints`.

3. **Sink (`Host/BTreeCommandSink.cs`):** add cases for `InsertReroute`/`MoveReroute`/`RemoveReroute` before the `default` arm.
   - Recover the child via `BTreeParentChildLink.ChildVisualIdFromLinkId(cmd.Link)`, find the `BTreeEditorNode` by VisualId.
   - InsertReroute → append `cmd.Position`; MoveReroute → range-guarded set `Waypoints[idx]=NewPosition`; RemoveReroute → range-guarded remove. Unknown child / out-of-range = safe no-op.
   - After mutation, do whatever the sink's other layout-ish mutations do to mark dirty / notify (mirror `ApplyMoveNodes` / `ApplySetNodeProperty`). Confirm the dirty/save path.

4. **Persistence — DTO + mapper:** add waypoints to the per-node editor metadata DTO.
   - Find the DTO (`Hrot.AiEditor.Persistence/BTree/BehaviorTreeAssetDto.cs` — `NodeEditorMetadataDto` with X/Y/Comment/Collapsed/Color). Add `List<WaypointDto> Waypoints` (or reuse an existing `{X,Y}` point DTO with **properties** so System.Text.Json round-trips; check whether the BTree services set `IncludeFields`). Make it omit-when-empty if other optional fields do, to keep existing JSON byte-stable.
   - Update the BTree mapper (`BehaviorTreeAssetMapper` ToDto/ToModel) to map `node.Waypoints` ↔ `dto.EditorMetadata.Waypoints`.

5. **Emitter — `[BTreeLayout]` (`Hrot.AiEditor.Persistence/Emit/BTreeEmitCore.cs`):** emit waypoints in the layout method **only when the node has any** (mirror how HSM's `HsmEmitCore` emits transition waypoints conditionally). A node with no waypoints must emit EXACTLY as today.
