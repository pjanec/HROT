# RR-02 — Blueprint wire reroute support

**Workstream:** RR (../RR-PLAN.md). **Layer:** Hrot.Blueprints.Editor + .Compiler asset model. **Depends:** none (pattern validated by RR-01). **Size: medium.**

## Goal

Handle `GraphCommand.InsertReroute / MoveReroute / RemoveReroute` in `BlueprintCommandSink` so users can add/drag/delete reroute points on Blueprint wires. The NodeEditor UI already emits these + renders dots/bent beziers. Blueprint links currently have NO waypoint store — add one that **persists + round-trips**.

## Key facts (verified)

- Link asset: `Hrot/Subsystems/Blueprints/Hrot.Blueprints.Compiler/Assets/GraphTypes.cs` — `sealed class Link { FromNodeId, FromPinId, ToNodeId, ToPinId }` (no id, no waypoints). Part of `Graph.Links` (serialized to the asset JSON).
- `BlueprintLinkModel` (`Editor/Host/BlueprintLinkModel.cs`): `Waypoints => Array.Empty<Vector2>()` (hard-coded); ctor is `(LinkId id, PinId fromPin, PinId toPin)`.
- `BlueprintGraphModel` (`Editor/Host/BlueprintGraphModel.cs:296-303`): builds each `BlueprintLinkModel` with `linkId = MakeLinkId(assetLink.FromPinId, assetLink.ToPinId)` — **a deterministic LinkId derived from the (FromPinId, ToPinId) pair, not stored.** `FindLink(LinkId)` → `_links` dict. `MakeLinkId` is the resolution key.
- `BlueprintCommandSink` has `_graph` (the `Graph`), `_model` (`BlueprintGraphModel`), `_markDirty`, and rebuilds/notifies the model after mutations (see how `ApplyMoveNodes`/`ApplyAddLink` finish — mirror that: mutate asset → `_markDirty(_asset)` + `_model.RebuildAndNotify()` or the existing notify call). Its `Apply` switch `default` silently accepts unknown commands — add explicit cases before it.

## Implementation

1. **Waypoint store on the asset (`GraphTypes.cs`):** add a waypoints list to `Link`.
   - **CRITICAL serialization caveat:** the asset is persisted with System.Text.Json, which by default does NOT serialize `System.Numerics.Vector2` (its X/Y are fields, not properties) — a raw `List<Vector2>` would round-trip as empty. **Before choosing the type, check how the Blueprint format already persists points/positions** (node positions live in `GraphMetadata`/node metadata — find the on-disk point representation). Mirror it: either reuse the existing serializable point type, or add a tiny `sealed class LinkWaypoint { public float X; public float Y; }` with **properties** (or whatever shape the existing positions use). Store `List<LinkWaypoint> Waypoints { get; set; } = new();` on `Link`. Use `[JsonIgnore(WhenWritingDefault/empty)]` only if other collections do; otherwise leave it (empty list is fine).
   - Decision rule: whatever makes a save→load→save round-trip byte-stable. Prove it with a test (below).

2. **Expose on the model (`BlueprintLinkModel` + `BlueprintGraphModel:302`):** pass the asset `Link` (or its waypoints) into `BlueprintLinkModel` so `Waypoints` returns the live list projected to `IReadOnlyList<Vector2>` (convert `LinkWaypoint`→`Vector2` if you used a DTO type). Update the construction site at `BlueprintGraphModel.cs:302` to pass it.

3. **Resolve LinkId → Link in the sink:** add a resolver — cleanest is an `internal Link? FindAssetLink(LinkId id)` on `BlueprintGraphModel` that iterates `_graph.Links` and returns the one whose `MakeLinkId(FromPinId, ToPinId)` equals `id` (reuses the canonical derivation; don't duplicate the hash). The sink calls it.

4. **Sink handlers (`BlueprintCommandSink`):** add cases before `default`:
   - `InsertReroute(Link, Position)` → resolve asset Link → append a waypoint (convert `Vector2`→your stored type).
   - `MoveReroute(Link, WaypointIndex, NewPosition)` → range-guarded set.
   - `RemoveReroute(Link, WaypointIndex)` → range-guarded remove.
   - Unknown LinkId / out-of-range = safe no-op returning `GraphCommandResult(true, null)`.
   - After a successful mutation: `_markDirty(_asset)` and rebuild/notify the model exactly as the other structural handlers do (so the canvas re-projects the new `BlueprintLinkModel` with updated waypoints). Reroute mutations are layout-ish; do NOT push them through `CommandHistory` unless the existing reroute-less editors do (match `ApplyMoveNodes`, which bypasses history).

## Constraints

- Scope: `GraphTypes.cs` (Link + optional waypoint type), `BlueprintLinkModel.cs`, `BlueprintGraphModel.cs` (ctor call + resolver), `BlueprintCommandSink.cs` (+ tests). Do NOT touch HSM/BTree/NodeEditor.
- Must not change existing Blueprint link behavior when there are no waypoints (empty list → straight wire, same as today).

## Tests (Blueprint editor test project)

- Sink: InsertReroute adds a waypoint to the correct Link (resolved via the derived LinkId); MoveReroute updates; RemoveReroute removes; out-of-range + unknown-LinkId = safe no-op.
- **Round-trip (mandatory — guards the Vector2 caveat):** build a Graph with a link, add a waypoint, serialize the asset to JSON and deserialize, assert the waypoint survived with correct X/Y. Use the project's existing blueprint serialize/deserialize path.
- Model projection: after adding a waypoint + rebuild, `BlueprintGraphModel.FindLink(id).Waypoints` returns it.
