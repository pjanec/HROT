| DEBT-MVE-003 | MVE-BATCH-05 (logged), MVE-BATCH-07 (upgraded) | **PRODUCTION BLOCKER — multi-blueprint hot-reload wipes siblings and dangles ALCs.** Root cause confirmed (MVE-BATCH-07): (1) `BlueprintRegistry.CommitStaging` fully replaces the snapshot (`BlueprintRegistry.cs:117-138`): `staging.Definitions.ToDictionary(...)` builds a brand-new dict from only the current staging buffer — every prior entry from other blueprints is gone. (2) `CSharpEmitter.EmitRegistrarClass(asset)` (`CSharpEmitter.cs:128`) emits exactly one registrar class per compile, covering only the blueprint being recompiled — no other assets are emitted. (3) `QuickReloadService.TriggerAsync` (`QuickReloadService.cs:51-186`) invokes only the newly compiled assembly's registrar into a single-entry `BlueprintRegistryStaging`, then passes that staging to `coordinator.ApplyQuickReload`. (4) `AiHotReloadCoordinator` tracks one `_currentAlc` field (`AiHotReloadCoordinator.cs:188-190`): on the next reload `oldAlc?.Unload()` unloads the previous assembly — including all delegates (`Tick`/`InitDefault`) from all OTHER blueprints compiled by a prior QuickReload. **Consequence with >1 editor-compiled blueprint:** quick-reloading blueprint A (a) WIPES definitions for blueprints B, C, … from the registry snapshot (full-replace with a 1-entry staging buffer), AND (b) leaves B/C's Tick/InitDefault delegates dangling in ALCs that get unloaded next reload → access violation on next tick of B or C. Invisible in single-blueprint MVE tests. **Fix sketch (do NOT implement here — architectural):** Option 1 (carry-forward + per-asset ALC): before CommitStaging, seed the staging buffer with all currently-live definitions EXCEPT the recompiled blueprint id (`for each (id, def) in _current.ById where id != recompiledId → staging.Add(id, def)`); AND track ALCs per-asset (dict<blueprintId, AssemblyLoadContext>) so only the recompiled asset's old ALC is unloaded, not others'. Option 2 (merge-commit + multi-ALC retention): add a merge mode to CommitStaging that upserts rather than replaces; retain all ALCs until no slot references their delegates. Option 1 is simpler but requires carry-forward of code-defined (non-ALC) definitions too; Option 2 requires registry and coordinator surgery. Either approach must be done atomically. **RESOLVED (BF01):** Implemented Option 2 — added `BlueprintRegistry.CommitStagingMerge` (upsert path, `BlueprintRegistry.cs:141-185`) so the quick-reload path preserves all sibling definitions; replaced the single `_currentAlc` in `Fdp.Toolkit.Behavior.AiHotReloadCoordinator` with a per-blueprint-id `_alcByBlueprintId` map so only the recompiled blueprint's old ALC is unloaded (`AiHotReloadCoordinator.cs:82,177-221`).
