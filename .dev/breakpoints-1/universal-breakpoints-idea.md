The vision for universal breakpoints transforms the engine's debugging capabilities from simple execution-flow pauses (like Blueprint nodes) into a comprehensive, time-traveling, data-driven diagnostic suite for the entire ECS engine. By combining the "soft pause" time-control architecture with the Replay Browser's query engine, we can pause the simulation based on arbitrary world-state changes without tanking frame rates or deadlocking the UI.
Here is the architectural blueprint for the universal breakpoint system:
1. The Condition Engine (Zero-Allocation Evaluation)
Instead of hardcoding breakpoint logic, we will repurpose the Replay Browser's existing highly-optimized evaluation compilers:
Component Data Breakpoints: We reuse the IPredicateCompiler, which takes JSON-friendly condition trees (SearchPredicateDto) and JIT-compiles them into Func<EntityRepository, Entity, bool> delegates. Because the compiler emits Expression Trees evaluating ref readonly T comp = ref repo.GetComponentRO<T>(entity), these checks execute directly against unmanaged chunk memory without boxing or allocations. It also natively handles managed components.
Transient Event Breakpoints: We reuse the EventScannerCompiler, which compiles TransientEventPredicateDto rules into EventScannerDelegate instances. This generates fast loops directly over the FdpEventBus double-buffers (bus.Read<T>() and bus.ReadManaged<T>()), allowing breakpoints to trigger when specific events (like HitEvent or DamageAssessedEvent) occur with specific payload values.
2. The Evaluation Phase (Optimized Hot Path)
To evaluate these breakpoints on live entities within our 60Hz frame budget, we will introduce a DataBreakpointSystem running in the SystemPhase.PostSimulation phase, or intercepting the EntityCommandBuffer playback. Instead of scanning the entire world, the system will use EntityRepository.QueryDelta. This delta query leverages chunk versioning to skip entire 64KB blocks of memory that haven't been touched, only evaluating our compiled breakpoint delegates against entities whose components actually changed during the current tick.
3. The Trigger Mechanism (The Soft Pause)
When a condition delegate evaluates to true, the system triggers the exact same soft-pause mechanism we built for Blueprints. It issues a call to the time controller to switch to lockstep mode (e.g., _masterSync.SwitchToDeterministic()). Because this is a "soft pause," it simply halts the advancement of the simulation clock on the next frame boundary. The OS thread does not block, and the engine's main loop continues to spin, allowing ImGui to render the debugging UI and the user to navigate the paused world.
4. Time-Travel and State Reconstruction (The Rewind)
Because the soft pause halts the engine at the end of the tick, the user would normally inspect the state after the breakpoint condition already occurred. To provide true mid-tick precision, we introduce a single-frame rewind mechanic:
Continuous Snapshotting: The engine already maintains persistent replicas via EntityRepository.SyncFrom() for Global Double Buffering (GDB). We will maintain a DebugSnapshotProvider that clones the world state at the very beginning of every tick.
State Swap on Pause: When a breakpoint hits, the editor UI's inspection context is instantly swapped to point at the snapshot repository. The user is now inspecting the exact ECS state right before the breakpoint triggered.
Re-simulating the Step: When the user clicks "Step", we overwrite the live EntityRepository with the snapshot (_liveRepo.SyncFrom(_snapshotRepo)). To guarantee deterministic re-simulation, we take the events captured by the EventAccumulator for that frame and push them directly back into the FdpEventBus read buffer using InjectEvents. The time controller is then commanded to advance exactly one 60Hz tick.
5. Flight Recorder Safety
To prevent this time-travel stepping from corrupting ongoing .fdp recordings with duplicate delta frames, the AsyncRecorder and RecorderTickSystem will be temporarily suspended during debug rewinds, or the recorder's write head will be rolled back to match the rewound tick.
This unified vision takes primitives we already built for network replication and replay searching, and wires them directly into the runtime simulation, creating a crash-proof, time-reversing data debugger for the entire engine.
