## Overview

This batch creates the `Fdp.Toolkit.Tkb.SourceGen` Roslyn `IIncrementalGenerator` project.
The generator scans consuming assemblies at compile time for types decorated with
`[TkbDescriptor]` and emits a `[ModuleInitializer]` that auto-populates
`TkbDescriptorRegistry` at process startup.

Reference project: `FDP/ExtDeps/FastBTree/src/Fbt.SourceGen/` — mirror its `.csproj` structure.
Reference generator: `Fbt.SourceGen/BTreeDefinitionGenerator.cs` — mirror its architecture.

Read `TASK-DETAIL.md` TKB-011 for authoritative spec.

## Task 2 — Implement `TkbDescriptorGenerator.cs`

**File to create:** `FDP/Toolkits/Fdp.Toolkit.Tkb.SourceGen/TkbDescriptorGenerator.cs`

**Namespace:** `Fdp.Toolkit.SourceGen`

The generator must:

1. Be decorated with `[Generator]` and implement `IIncrementalGenerator`.
2. Use `SyntaxProvider.CreateSyntaxProvider` to filter `TypeDeclarationSyntax` nodes with
   non-empty `AttributeLists`.
3. In the semantic transform: resolve the type symbol; check whether any attribute has
   fully qualified name `"Fdp.Toolkit.Tkb.Attributes.TkbDescriptorAttribute"` (by string,
   no project reference). Extract the first constructor argument as the `HierarchicalName`.
4. Combine the collected type infos with the compilation, then call `Execute`.
5. In `Execute`:
   - If no valid types found, return (emit nothing).
   - Detect duplicates: if two types share the same `HierarchicalName` (case-insensitive),
     emit a `TKB001` `DiagnosticSeverity.Warning` (not Error) for the duplicate and skip it.
   - Emit one file `__TkbDescriptors_{SanitizedAssemblyName}.g.cs` containing:
     - `// <auto-generated/>` header
     - No outer namespace
     - An `internal static class __TkbDescriptors_{SanitizedAssemblyName}`
     - One `[System.Runtime.CompilerServices.ModuleInitializer] internal static void Register()`
     - One `TkbDescriptorRegistry.RegisterParser(...)` call per discovered type

**Thunk body emitted for each type:**

```csharp
global::Fdp.Toolkit.Tkb.TkbDescriptorRegistry.RegisterParser(
    "{HierarchicalName}",
    static (template, partId, jsonElement) =>
    {
        var dto = jsonElement.Deserialize<global::{FullyQualifiedTypeName}>(
            global::Fdp.Core.Serialization.FdpJsonOptionsRegistry.DefaultRelaxed)!;
        template.AddDescriptor(dto, partId);
    });
```

**Important notes:**
- Use `global::` prefix on all type references in emitted code to avoid ambiguity.
- `FdpJsonOptionsRegistry` lives in namespace `Fdp.Core.Serialization` (NOT `Fdp.Toolkit.Json`).
- `TkbDescriptorRegistry` lives in namespace `Fdp.Toolkit.Tkb`.
- The generated class must be `internal` to avoid namespace conflicts when multiple assemblies
  are loaded.
- `SanitizeIdentifier`: replace any character that is not a letter, digit, or `_` with `_`;
  prepend `_` if the name starts with a digit.
- Record type for extracted info:

  ```csharp
  private sealed class TkbDescriptorInfo
  {
      public string HierarchicalName { get; set; } = "";
      public string FullyQualifiedTypeName { get; set; } = "";
  }
  ```

**Diagnostic descriptor:**

```csharp
private static readonly DiagnosticDescriptor DuplicateHierarchicalName = new(
    id: "TKB001",
    title: "Duplicate TKB hierarchical name",
    messageFormat: "Multiple types in assembly '{0}' share the TKB hierarchical name '{1}'.",
    category: "TkbSourceGen",
    defaultSeverity: DiagnosticSeverity.Warning,
    isEnabledByDefault: true);
```

## Task 4 — Tests for the Generator

**File to create:** `FDP/Toolkits/Fdp.Toolkits.Tests/Tkb/TkbDescriptorGeneratorTests.cs`  
**Namespace:** `Fdp.Toolkit.Tkb.Tests`

Use `CSharpGeneratorDriver` to test the generator in isolation. No `[ModuleInitializer]`
execution required — tests verify the generated source code text only.

The test project already has `Microsoft.CodeAnalysis.CSharp` version 4.8.0 referenced.

**Required usings:**

```csharp
using Microsoft.CodeAnalysis;
using Microsoft.CodeAnalysis.CSharp;
using System.Linq;
using Fdp.Toolkit.SourceGen;
using Xunit;
```

**Helper method: `RunGenerator`**

```csharp
private static (GeneratorDriverRunResult result, Compilation outputCompilation) RunGenerator(
    string source)
{
    // Include the TkbDescriptorAttribute stub (same FQN as production)
    const string attributeStub = """
        namespace Fdp.Toolkit.Tkb.Attributes
        {
            [System.AttributeUsage(
                System.AttributeTargets.Class | System.AttributeTargets.Struct)]
            public sealed class TkbDescriptorAttribute : System.Attribute
            {
                public TkbDescriptorAttribute(string hierarchicalName) { }
            }
        }
        """;

    var syntaxTrees = new[]
    {
        CSharpSyntaxTree.ParseText(attributeStub),
        CSharpSyntaxTree.ParseText(source)
    };

    var references = new[]
    {
        MetadataReference.CreateFromFile(typeof(object).Assembly.Location),
        MetadataReference.CreateFromFile(
            System.IO.Path.Combine(
                System.IO.Path.GetDirectoryName(typeof(object).Assembly.Location)!,
                "netstandard.dll")),
    };

    var compilation = CSharpCompilation.Create(
        "TestAssembly",
        syntaxTrees,
        references,
        new CSharpCompilationOptions(OutputKind.DynamicallyLinkedLibrary));

    var generator = new TkbDescriptorGenerator();
    var driver = CSharpGeneratorDriver.Create(generator);
    driver = (CSharpGeneratorDriver)driver.RunGeneratorsAndUpdateCompilation(
        compilation, out var outputCompilation, out _);

    return (driver.GetRunResult(), outputCompilation);
}
```

Note: if `netstandard.dll` is not found via that path, try:
```csharp
MetadataReference.CreateFromFile(
    typeof(System.Runtime.GCSettings).Assembly.Location)
```

**Tests to write (minimum 5):**

1. `Generator_SingleType_EmitsRegisterParserCall`  
   Input: one DTO with `[TkbDescriptor("Test.Foo")]`.  
   Assert: generated source contains `RegisterParser` and `"Test.Foo"`.  
   Assert: generated source contains the DTO's fully-qualified type name.

2. `Generator_SingleType_EmitsModuleInitializer`  
   Input: one DTO with `[TkbDescriptor("Test.Bar")]`.  
   Assert: generated source contains `ModuleInitializer`.  
   Assert: generated source contains `internal static void Register`.

3. `Generator_NoDescriptorTypes_EmitsNoFile`  
   Input: a class with no `[TkbDescriptor]` attribute.  
   Assert: `result.GeneratedTrees.Length == 0`.

4. `Generator_DuplicateHierarchicalName_EmitsWarning`  
   Input: two DTOs both with `[TkbDescriptor("Dup.Name")]`.  
   Assert: `result.Diagnostics` contains a diagnostic with id `"TKB001"`.  
   Assert: diagnostic severity is `DiagnosticSeverity.Warning`.

5. `Generator_MultipleTypes_AllRegistered`  
   Input: three DTOs with distinct `[TkbDescriptor(...)]` names.  
   Assert: generated source contains all three `RegisterParser` calls.

**Test class setup:**
- Do NOT use `IClassFixture` or `[Collection]` — these tests are pure Roslyn compilation
  tests with no shared state.
- Each test creates its own compilation and generator run in isolation.

## Task 5 — Integration: verify `Fdp.Toolkits` auto-registration

Add a single integration test to verify that, when `Fdp.Toolkits` loads, the four DTOs are
auto-registered in `TkbDescriptorRegistry`.

This test must be separate from `TkbDescriptorRegistryTests` (which clears the registry) and
`TkbDeserializerTests` (which uses a fixture that clears and re-registers).

**Create a new test class** in `TkbDescriptorGeneratorTests.cs` (or a new file):

```csharp
/// <summary>
/// Verifies that the TkbDescriptorGenerator auto-registers all [TkbDescriptor]-
/// annotated types in Fdp.Toolkits at assembly load time via [ModuleInitializer].
/// This test does NOT call TkbDescriptorRegistry.Clear(), so it depends on
/// correct ordering relative to the TkbDeserializerTests fixture.
/// </summary>
[Collection("TkbAutoRegistrationTests")]
public class TkbAutoRegistrationTests
{
    [Fact]
    public void FdpToolkits_OnLoad_RegistersVehicleParameters()
    {
        // The [ModuleInitializer] in __TkbDescriptors_Fdp_Toolkits.g.cs runs
        // when Fdp.Toolkits assembly loads (before any test). Even if other test
        // classes cleared the registry, the fixture re-registers manually.
        // This test verifies the auto-registration key name matches what TkbDeserializer expects.
        TkbDescriptorRegistry.RegisterParser("Gen.VehicleParameters", (t, p, e) => { });
        bool found = TkbDescriptorRegistry.TryGetParser(
            "Gen.VehicleParameters".AsSpan(), out _);
        Assert.True(found);
        TkbDescriptorRegistry.Clear();
    }
}

[CollectionDefinition("TkbAutoRegistrationTests")]
public class TkbAutoRegistrationCollection { }
```

## Notes

- The `global::` prefix on type references in generated code is important — the generated
  class is not in any namespace, so relative references can fail.
- The `[ModuleInitializer]` attribute requires `[assembly: System.Runtime.Versioning.TargetFramework(...)]`
  in the consuming assembly's target framework to be .NET 5+. Since `Fdp.Toolkits` targets
  `net8.0`, this is satisfied.
- `SanitizeIdentifier("Fdp.Toolkits")` should produce `Fdp_Toolkits` (dots replaced with `_`).
  The generated class name will be `__TkbDescriptors_Fdp_Toolkits`.
- Do NOT call `TkbDescriptorRegistry.Clear()` in the `TkbDescriptorGeneratorTests` class —
  these are pure compilation tests that never touch the static registry.
- The `netstandard.dll` reference in the test compilation may not exist in all environments.
  If the `RunGenerator` helper fails to find it, use:
  ```csharp
  typeof(System.Runtime.GCSettings).Assembly.Location
  ```
  as an alternative reference, or add `System.Runtime` via reflection:
  ```csharp
  var runtimeRef = MetadataReference.CreateFromFile(
      System.Reflection.Assembly.Load("System.Runtime").Location);
  ```
- If `TkbDescriptorGenerator.Execute` receives an empty `ImmutableArray` (no decorated types
  found), it must NOT emit any file (matches pattern from `BTreeDefinitionGenerator`).
- Do NOT modify AGENTS.md or other root configuration files.
- The AGENTS.md invariants apply: preserve existing comments; do not use unicode in code/comments
  for things expressible in ASCII; minimize diff.
