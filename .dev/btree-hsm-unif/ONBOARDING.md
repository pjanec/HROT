# BTree + HSM Unification — Onboarding Guide

## What Is This Workstream?

This workstream makes BTree and HSM behaviors interchangeable in `Hrot.AI.Behaviors`.
At the end of all phases, a CGF unit's tactical brain can be authored in either
Behavior Tree (FastBTree) or Hierarchical State Machine (FastHSM) without the editor,
mission director, or interrupt system needing to know which paradigm is running.

## Key Concepts

### BTree (FastBTree)

A behavior tree encodes reactive decision logic as a composable node graph.  
Entry point: `FDP/ExtDeps/FastBTree/src/`

- **`Fbt.Kernel`**: runtime tick engine, `BehaviorTreeBlob` (compiled tree), hot reload
  watcher (`FbtAssemblyHotReloader`)
- **`Fbt.Compiler`**: fluent `BTreeBuilder<TBlackboard, TContext>` API
- **`Fbt.SourceGen`**: Roslyn generator — scans `[BTreeAction]`/`[BTreeCondition]` and
  emits `FbtActionRegistrar.g.cs`
- **`BrainBTreeState`**: ECS component holding the live tree state (64 bytes)
- Behaviors defined in `Hrot.AI.Behaviors/AiBehaviorFactory.cs` and
  `Hrot.AI.Behaviors/Brains/CgfNodes.cs`

### HSM (FastHSM)

A hierarchical state machine encodes event-driven behavior with nested states.  
Entry point: `FDP/ExtDeps/FastHSM/src/`

- **`Fhsm.Kernel`**: runtime tick/event engine, `HsmDefinitionBlob` (compiled state
  machine), `HotReloadManager` (live-instance migration), `HsmActionDispatcher` (global
  static action/guard pointer table — generated by `Fhsm.SourceGen`)
- **`Fhsm.Compiler`**: fluent `HsmBuilder` API — `State()`, `On()`, `GoTo()`, `Final()`
- **`Fhsm.SourceGen`**: Roslyn generator — scans `[HsmAction]`/`[HsmGuard]` and emits
  `HsmActionRegistrar.g.cs` (user assembly) and `HsmActionDispatcher.g.cs` (kernel)
- **`BrainHsm64` / `BrainHsm128`**: ECS components (64 / 128-byte fixed buffers)
- Behaviors will be defined in the same `AiBehaviorFactory.cs` as BTree behaviors

### ECS and Toolkit

`FDP/Toolkits/Fdp.Toolkits/Behavior/` contains the ECS systems that run each frame:

| System | Purpose |
|--------|---------|
| `ChannelArbitrationSystem` | Resets channels on behavior change |
| `CognitiveInterruptSystem` | Writes interrupt flags to `BrainBlackboard` (Phase 3) |
| `BTreeTickSystem` | Ticks BTree instances; publishes `BehaviorFinishedEvent` |
| `HsmTickSystem<BrainHsm128>` | Ticks 128-byte HSM instances |
| `HsmTickSystem<BrainHsm64>` | Ticks 64-byte HSM instances |

### Hot Reload

`Hrot.Editor` watches `Hrot.AI.Behaviors.dll` for changes. When the DLL is rebuilt, the
coordinator loads it into a fresh `AssemblyLoadContext`, extracts BTree + HSM blobs, and
applies them at the next frame boundary.

## Build

```
dotnet build IOS-IG-SimHost.sln
```

Or for the libraries only (faster iteration):

```
dotnet build FDP/FDP.sln
```

The `Hrot.AI.Behaviors` project can be rebuilt in isolation when developing behaviors:

```
dotnet build Hrot/Subsystems/Hrot.AI.Behaviors/Hrot.AI.Behaviors.csproj
```

Copy the output DLL to the watch directory to trigger hot reload in a running editor.

Batch A (for the attribute classes to compile in user assemblies). Batch F requires
Batch E.

## Important Invariants

1. **`HsmActionDispatcher.ClearAll()` and `RegisterAll()` must run on the main thread.**
   The `ActionTable`/`GuardTable` dictionaries are not thread-safe. Always call them
   from inside `DrainPendingCallbacks()`, never from the background reload thread.

2. **`InstanceHeader` is always at offset 0 in `BrainHsm64` and `BrainHsm128`.**
   `Unsafe.As<T, InstanceHeader>` is the only safe way to access it generically.
   Do not use `Unsafe.AsPointer` or manual offset arithmetic for this cast.

3. **BTree blobs bake in action delegates; HSM blobs do not.**
   After a BTree reload, old blobs and new blobs can co-exist temporarily.
   After an HSM reload, `HsmActionDispatcher` must be fully refreshed before any
   instance ticks, because it is the single global dispatch table for all instances.

4. **`StateFlags.IsFinal` requires both compiler support (BHU-005) and kernel support
   (BHU-006) to be useful.**
   BHU-005 alone does nothing at runtime — the flag is set in the blob but ignored by
   the kernel until BHU-006 is also applied.

5. **The compound key `"MethodName@offset"` must be consistent between `Fbt.SourceGen`
   and `Fhsm.SourceGen`.**
   If the format ever changes, both generators and all behavior JSON/DSL files referencing
   shared nodes must be updated together.
