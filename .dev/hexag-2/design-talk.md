An event bus exists to be the integration backbone for decoupled modules. When you partition it, you fragment your simulation state and force error-prone synchronization boilerplate—which inevitably leads to dropped events when a developer accidentally deletes a bridging loop.

To fix this properly and unify the event architecture, you must eliminate the isolated buses and rely on a single source of truth. 

**Steps to Unify the Event Buses:**

1. **Eliminate Redundant Instances:** Remove the separate `_orchestrationBus` and `_eventBus` fields in `OrchestratorSubsystem`. Declare a single, unified bus: 
   `private readonly FdpEventBus _bus = new FdpEventBus();`
2. **Unified Dependency Injection:** Inject this single `_bus` instance into all components across the subsystem. The `ClusterMaster`, `NodeOpSlaveTranslator`, `ClusterUiCache`, and `MasterSyncController` must all share this exact reference.
3. **Remove Bridging Hacks:** Delete any remaining logic that exists purely to ferry events between local buses. Because `ClusterUiCache` and `MasterSyncController` will now share the same bus, the UI will natively observe the `SwitchTimeModeEvent` as soon as it is published.
4. **Strict Phase Swapping:** Consolidate your `SwapBuffers()` calls. A unified bus requires strict phase discipline. You should only call `_bus.SwapBuffers()` at defined boundaries within the `Update(float deltaTime)` loop, ensuring that all upstream system writes (like time mode transitions) are atomically committed to the read buffer before downstream consumers (like the UI cache) execute.

The correct, clean architecture requires neither double-swapping nor bus-fragmentation. It relies on a **Single Unified Bus** with exactly **One Swap Per Frame**, achieved through strict phase discipline.

To implement this properly, your `Update()` loop must follow this exact sequence:

1. **Phase 1: Network Boundary (Egress & Ingress)** Your translators must execute first. `ScanAndPublish` reads the stable outputs generated by the logic layer during the *previous* frame. `PollIngress` polls CycloneDDS and writes new incoming network events to the bus's pending write buffer.
2. **Phase 2: The Single Frame Boundary Swap** Call `_bus.SwapBuffers()` exactly once. This atomically commits the new network ingress events to the read buffer and wipes the old egress outputs that have now been successfully transmitted.
3. **Phase 3: Core Logic** Your core components (`ClusterMaster`, `MasterSyncController`) execute. They consume the fresh network intents from the read buffer, mutate internal state, and publish new outputs (like `AdvanceFrameIntent`) to the pending write buffer.
4. **Phase 4: Local Observation (UI)** The `ClusterUiCache` and presentation layer execute. In a strict ECS architecture, the UI should tolerate a 1-frame delay for event-driven updates, or it should poll the authoritative read-models (like `MasterSyncController`'s state) directly.
