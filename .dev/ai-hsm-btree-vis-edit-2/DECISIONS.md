## TASK-BT-01 — Live action/condition palette
- **D-01 (2026-06-12): Action-vs-Condition discriminator.** `ActionSchemaEntry`/`BehaviorActionEntry` do NOT record whether an entry is an action or a condition (`ActionSchemaExporter.ProcessMethod` collapses `[BTreeAction]` and `[BTreeCondition]` both into `Hosting |= BTree`; same for `[SharedAi(Heavy)Action/Condition]`). **Decision:** add `bool IsCondition` to `ActionSchemaEntry` **appended with a default (`= false`)** so existing positional call sites & BB1 tests keep compiling, and set it `true` in the `[BTreeCondition]` / `[SharedAiCondition]` / `[SharedAiHeavyCondition]` branches of `ProcessMethod`. Additive, BB1-safe (BB1 reads `DtoType`, unaffected). Rejected alternatives: per-entry reflection in the catalog (ugly/slow); duplicate attribute scan in the catalog (duplicates exporter logic). Guardrail: BATCH-01 must keep `Hrot.Editor.AiShared.Tests` 0-new-failures (covers `ActionSchemaExporterTests` + BB1 picker tests).
- **D-02 (2026-06-12): Placement bakes identity via encoded NodeKindKey.** Specific entries use kind id `bt.leaf.action::{Fqn}` / `bt.leaf.condition::{Fqn}` (`::` separator — FQNs contain dots). `BTreeKinds` gains a parse helper; `BTreeCommandSink.ApplyAddNode` detects an encoded action/condition kind and sets `node.KernelType = Action|Condition` + `node.Action`/`node.Condition` payload (`MethodFqn = fqn`). Generic `bt.leaf.action` / `bt.leaf.condition` entries remain as unbound fallbacks.

## TASK-BT-10 — BTree vertical pin orientation (REVIEW-BT F3)
- **D-06 (2026-06-12, user-confirmed): vertical orientation flag; parent-pin top / child-pin bottom; NO fan-out-rule change.** Add a per-graph-kind "vertical" orientation option to NodeEditor (`CanvasLayoutBuilder` pin-position math + label/inline-editor positioning); Blueprint/HSM stay horizontal (opt-in). ## TASK-BT-06 — Showcase + Starter recipe
- **D-05 (2026-06-12): showcase drops the bound Condition guard (real architectural gap).** The BTree generator emits `obs.Condition(Method, …)` expecting a 4-param `NodeLogicDelegate<BrainBlackboard,BTreeContext>`, but **every** real `[BTreeCondition]` in the codebase takes a typed DTO param (FireAtTargetParams, MoveToOptimalCoverParams, …) — none has the 4-param/BrainBlackboard shape, and `BrainBlackboard` exposes no DTO-typed field for the `ThreeParamReusable` expression-target path. So a real condition cannot be bound into a BrainBlackboard-typed *generated* tree that compiles, without the expression-target/blackboard-field machinery (BB1-adjacent). The BATCH-06 worker hacked around this by adding a bogus `Unsafe.As<BrainBlackboard,FireAtTargetParams>` 4-param overload to production `CgfNodes.cs` (duplicate-FQN `[BTreeCondition]` + meaningless reinterpret) — **REJECTED** (unauthorized production edit + cheating-to-compile). **Resolution:** revert `CgfNodes.cs`; the showcase's ObserverSelector keeps its Sequence child but **drops the bound Condition guard** (everything else — pills, real `Action_Wander`, Wait, Subtree→SampleScout — codegens cleanly). The OBSERVES-badge + real-condition-binding demo is deferred → **VE-DEBT-002**.
