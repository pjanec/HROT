## Prerequisites (folded into tasks — tracked here for visibility)
- [ ] **DEBT-AIB-001 — `bool` `[MarshalAs(I1)]` latent bug.** `BlackboardDtoEmitter` emits bare `bool`; bin-packer assumes 1 B but `Marshal.OffsetOf` defaults 4 B → silent offset drift / broken replay schemas. **Owned by task S1-0** (must precede S1-2). AIB-DD §3.2.
- [ ] **DEBT-AIB-002 — bin-packer C# sequential-layout fidelity.** Editor bin-packer must exactly replicate C# `Sequential` layout (natural alignment capped at 8; padding before `fixed`/`[InlineArray]` fields), else advisory offsets diverge from compiled `Marshal.OffsetOf`. S1-2 tests cover `{int,Vector3,bool}`; **add a `fixed`/`[InlineArray]` padding case** before relying on heavy/array variables. AIB-DD §2.

## Resolved
- [x] **DEBT-AIB-019 (P0, found+fixed 2026-06-15) — editor crash clicking a variable row with a comment.** In `VariablesPanelControl.DrawTable`, a commented row emitted `TextDisabled(comment)` (no ImGui ID) between the row `Selectable` and `BeginDragDropSource`, so the drag source attached to a no-ID item → `IM_ASSERT(0)` ("Expression: 0", kills app) on click. Both T10 vars have comments → every click crashed. **Fix:** moved the comment `SameLine/TextDisabled` to after the drag-source/target blocks so the drag attaches to the `Selectable`. (Also fixed the analogous unbound-requirement rows earlier, commit 8b80cf73.) Audited the file for other no-ID drag sources — none. ImGui-assert not headless-testable; verified by review + AiShared 1103/0. Editor app is NOT hot-reloaded → user must rebuild+restart.
- [x] **DEBT-AIB-020 (found+fixed 2026-06-15, architect-confirmed) — aggregator double-counted locally-bound nodes.** `BTreeBlackboardAggregatorStrategy` emitted a `DtoRequirement` for every action/condition node, ignoring `ExpressionTargetField` → locally-bound nodes appeared under "UNBOUND SUB-TREE REQUIREMENTS" and were added to the byte budget on top of the variable they bind (T10: 40 B instead of 16 B). **Fix:** skip emission when `ExpressionTargetField` is populated (architect ruling: the bound variable IS the slot; aliasing counts once; sub-tree requirements still count until aliased; no under-count risk). HSM aggregator unaffected (HSM doesn't use ExpressionTargetField on visited action payloads). +5 aggregator tests (BTree.Editor 568/0).
- [x] **DEBT-AIB-015 (P0, found+fixed 2026-06-15) — editor crash opening a managed asset with a struct-DTO variable.** `ResolveClrType` (BTree + HSM mappers) used only `Type.GetType(typeId)`, which can't see DTO struct types in behavior assemblies (e.g. `DemoCounterNodes+DemoCounterParams`) → fell back to `typeof(object)` → `BlackboardBinPacker.GetManagedSize`→`Marshal.SizeOf(object)` threw. **Fix:** search loaded assemblies by full name. Regression tests `ManagedStructDtoLoadTests` (BTree.Editor.Tests). Reported by user opening T10.
- [x] **DEBT-AIB-016 (P0, found+fixed 2026-06-15) — editor crash: duplicate aggregated DTO-requirement names.** `BlackboardAuthoringWindow.BuildViewModel` built its size map with `pack.Variables.ToDictionary(pv => pv.Name)`; aggregated descriptors are named by `DtoType.Name`, so multiple nodes binding the same DTO type (T10: condition + action both → `DemoCounterParams`) produced duplicate names → ArgumentException. **Fix:** dedup (last-write-wins; same name = same type = same size). Regression test `BuildViewModel_DuplicateAggregatedDtoRequirements_DoesNotThrow`. Reported by user opening T10.
- [x] **DEBT-AIB-017 (pre-existing, fixed 2026-06-15) — `Hrot.Hsm.Editor.Tests` did not compile.** `StubBlackboardAsset` (HsmValidatorBlackboardConflictTests) lacked `IBlackboardManagedAsset.SetBlackboardEditorManaged` (interface member added in 90c19d52, prior session) → whole HSM editor test project failed to build, masking HSM editor coverage. Added the stub method (now 497/0). Not this workstream's regression; unblocked while verifying the HSM mapper fix.
- [x] **DEBT-AIB-014 (P0, found+fixed 2026-06-15) — editor startup crash: null BTree ActionRegistry.** The production `Hrot.Editor.AiHotReloadCoordinator.DrainPendingCallbacks` resolved registrar params via `ResolveRegistrarParam`, which had NO case for `ActionRegistry<BrainBlackboard,BTreeContext>` → passed `null` → the generated bridge's `new Interpreter(blob, registry)` threw `ArgumentNullException('registry')` at startup (e.g. `BTreeRenderShowcaseRegistrar`). Latent gap from the PREREQ-A bridge-signature change; my S1 test coverage only exercised the test-seam coordinator, not this production path. **Fix:** build a populated registry via `BTreeActionRegistryFactory.BuildFromAssembly(registrar assembly)` and inject it for that param type (mirrors the `Fdp.Toolkit` coordinator). Regression test `Drain_InjectsNonNullBTreeActionRegistry_ForBridgeRegistrar` (Hrot.Editor.Tests 186/0). Reported by user running the app.
