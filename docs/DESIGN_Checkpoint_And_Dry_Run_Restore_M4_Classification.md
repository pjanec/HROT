# M4 classification: NoReplay / Transient types vs checkpoint restore

**Counts:** types carrying NoReplay = 103; events = 57; components/singletons = 46 (15 singletons, 31 per-entity components; 27 are `Transient`, 19 are NoReplay without NoPreview). Per class: SIM-STATE 9, PROTOCOL 18, NET-SHADOW 5, EDITOR-DEBUG 4, ONE-SHOT 9, UNCLEAR 1. Plus 4 NoPreview-only types (recorded, outside the restore question).

## Facts established while classifying

- **Singletons are NOT cleared by a keyframe restore.** `EntityRepository.Clear()` (FDP/Engine/Fdp.Core/EntityRepository.cs:429-447) clears `_componentTables` and the event bus only; singletons live in a separate `_singletons` array (EntityRepository.cs:66, 1928-2052). `PlaybackTickSystem.cs:192` says so too ("SoftClear, singletons kept"). So for the 15 singleton types below "empty after restore" is not what happens: they keep their live pre-restore value (never emptied, never rewound). None of the singletons is SIM-STATE.
- **Only per-entity components become empty.** `PlaybackSystem.cs:55` calls `repo.Clear()` on a keyframe, then restores recorded singletons (:77-82) and chunks (~:85-108). Policy flags are applied at registration (EntityRepository.cs:632-740): `NoReplay` => not recordable => skipped by RecorderSystem for tables (:226,440) and singletons (:849); events are filtered separately (RecorderSystem.cs:693-701, 824-831).
- **Re-flood hook:** after a seek `PlaybackTickSystem` calls `SmartEgressUtil.ForceMarkAllDirty` (PlaybackTickSystem.cs:175,183) plus `_afterSeek` (entity map rebuilt, lifecycle bookkeeping reset). `ForceMarkAllDirty` only touches entities that still have an `EgressPublicationState` (itself NoReplay), so in practice the lazily recreated empty state does the work: absent state => `ShouldPublish` returns true (SmartEgressUtil.cs:92).
- **PROTOCOL here is also the bucket for process-local / native / asset-derived caches** (terrain, SUMO net, ring buffers) that are re-derived, not restored; none of the six requested classes fits them better.
- **Method / coverage:** symbol lookups used `scripts/cbm.sh search_graph` (SubordinateOrders, PausedTask, AirPath); `check_index_coverage` is not available through the CLI, so every writer/reader list below comes from grep over `FDP Hrot Stride` (tests, examples, benchmarks excluded) and is NOT proven exhaustive (interface dispatch, reflection and `Query().With<T>()` sites can hide readers). The graph does not model component reads/writes, so it could not corroborate them.

## NoPreview vs NoReplay set difference

Flags are read from `[DataPolicy(...)]` only; no production call passes a `DataPolicy` override to `RegisterComponent` / `RegisterManagedComponent` (grep). Unattributed mutable (non-record) managed classes default to `NoPreview` only (EntityRepository.cs:722-726) and are recorded; they cannot be enumerated by attribute and are not listed.

**NoPreview WITHOUT NoReplay (4; all `NoScenario|NoPreview`, so RECORDED and restored, out of scope for this question):**

## Defects (every SIM-STATE type; these must become recordable)

Each is a per-entity managed class on a Brain or Muscle entity, `Transient`/NoReplay, so the keyframe drops it and `Clear()` empties it. Ordered by how directly a restored run diverges.

- **PausedTask** (FDP/Toolkits/Fdp.Toolkits/Behavior/Components/PausedTask.cs:17): a reaction that ends after a restore does not resume the interrupted task; the unit falls to the SOP/idle choice.
- **SubordinateOrders** (FDP/Toolkits/Fdp.Toolkits/Behavior/Components/SubordinateOrders.cs:17): commander forgets which orders its run gave: orders are not cleared when the run ends, and `Stands/Gave/StillRunning` report false so plays re-send (restarting posted members).
- **BehaviorStartRecord** (FDP/Toolkits/Fdp.Toolkits/Behavior/Components/BehaviorStartRecord.cs:27): `RunningIs` false, `PauseRecord` null (no pause/resume), UrbanMovement route unreadable, brain hand-over cannot read the intent, hot-reload restart uses defaults.
- **SopStartRecord** (FDP/Toolkits/Fdp.Toolkits/Behavior/Components/SopState.cs:67): hosted-occurrence keys lost: a task start resets the SOP hosted children, `EndSop` leaks their slots (lower severity).
- **AirPath** (FDP/Toolkits/Fdp.Toolkits/Motion/AirRoute.cs:34): follower state lost: the route restarts from the current position, holds/drops/orbit phase repeat.
- **MissionAdapterState** (Hrot/Subsystems/Hrot.CGF/Components/MissionAdapterState.cs:29): current mission phase re-dispatched (restart), or a repeated Superior clear for an exhausted plan.
- **SensorCapability** (FDP/Toolkits/Fdp.Toolkits/Perception/Components/SensorComponents.cs:40): per-sensor range/FOV/modality and the override Default are gone; TKB children are only built at spawn.
- **SensorConfigPayload** (FDP/Toolkits/Fdp.Toolkits/Perception/Components/SensorComponents.cs:53): a Brain sensor override (or survey request on the wire) silently reverts.
- **WorldSurveyRequest** (FDP/Toolkits/Fdp.Toolkits/Perception/Survey/WorldSurveyModel.cs:60): `Ensure()` never re-sets the request on an existing child, so the survey stops solving for behaviours that Ensure once per run.
